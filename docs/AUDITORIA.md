# Auditoría de E2 — LEVEL UP 2.0

Fecha de corte: **11 de noviembre de 2026, America/Guayaquil**. **T-19 y T-20: cierre local verificado**. Las últimas suites de dominio, backend, UI y navegador pasaron después de los ajustes compatibles de dependencias. La entrega pública, el despliegue y las evidencias específicas de Claude Code no se declaran completados.

## Alcance y fuentes

Fuentes de verdad: [PRD](prd/level-up.md), [backlog](backlog/E2-metas-y-rachas.md), [spec backend](specs/E2-backend-metas-progreso.md), [spec frontend](specs/E2-frontend-metas-rachas.md), [diagnóstico](diagnostico.md), [enunciado](referencias/enunciado-E4.md), [AGENTS.md](../AGENTS.md) y [DESIGN.md](../DESIGN.md). No se modifican producto, criterios ni asignaciones.

Las tablas conservan una fila por criterio de **cada spec: 50 backend + 49 frontend = 99 filas; 56 IDs distintos**. Los tickets reproducen sus asignaciones aprobadas. Un criterio compartido se audita en cada capa.

**P/U**: dominio o unitaria sin DB. **HTTP**: Express real con persistencia/driver simulados. **S/C**: servicio/componente con dobles. **E**: Edge real con API interceptada. **I**: HTTP y MongoDB reales en replica set efímero. **R**: Edge → API Express → MongoDB reales, sin interceptar peticiones. «Aprobado» acredita únicamente el nivel y los casos descritos; ningún conjunto finito prueba todos los fallos o intercalaciones posibles.

## Hallazgos y límites finales

La revisión del ejecutor detectó que Playwright termina procesos forzosamente en Windows, sin garantizar sus manejadores de señales. El cierre final usa un POST exclusivo del servidor de pruebas y un `globalTeardown`: exige `200 {cerrado:true}` después de desconectar MongoDB y confirmar `replica.stop()`. Se desactivó la caché auxiliar de tsx antes de importarlo. La última suite R pasó con este cierre; no se atribuye limpieza retroactiva a rondas anteriores. Evidencia: [servidor efímero](../backend/tests/soporte/servidor.cjs), [confirmación de cierre](../frontend/scripts/cerrar-integracion.mjs). El plazo de 15 segundos del cliente es un límite de espera para detectar fallos, no una garantía remota absoluta.

1. La integración real detectó un defecto ausente en mocks: crear una meta duplicada con hitos devolvía201/500 por un `StrictModeError` interno de Mongoose. El RED real motivó limitar `versionKey:false` al esquema embebido Hito, conservando `strict:"throw"`; el resultado pasó a409 real y se añadió regresión unitaria. [Meta.model.ts](../backend/src/modelos/Meta.model.ts), [meta-validacion.test.ts](../backend/tests/meta-validacion.test.ts) y [suite I](../backend/tests/integracion/e2-real.test.ts).
2. I comprueba rollback en fallos de comandos y recuperación de un `UnknownTransactionCommitResult` nativo código64 durante un commit. No cubre una partición de red persistente, caída de nodo o resultado desconocido terminal. El presupuesto de 10 segundos sigue siendo cooperativo, sin promesa de duración total/interrupción remota; no se añadieron reintentos destructivos.
3. Los casos frontend faltantes detectados en la primera matriz se complementaron con R:1,6/53,3,5/70, días deduplicados, meta sin actividad, racha rota, medianoche, reversión de hito, histórica, conflicto del formulario E1 y borrado confirmado. Las filas señalan cuando un caso exacto se verifica por capas y no por un recorrido UI exclusivo.
4. Los artefactos de navegador/contraste son locales y regenerables; repetir/comprobar al cerrar entrega. Las suites usan datos sintéticos y DB efímera; no autorizan probar contra Atlas ni implican prueba de producción.
5. Persisten avisos de dependencias y las deudas diferidas del diagnóstico. La revisión de contraste/responsive no certifica WCAG global. Los hooks no fueron verificados dentro de Claude Code.
